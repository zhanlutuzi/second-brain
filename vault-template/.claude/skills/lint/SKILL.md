# 体检

页面格式和主题页粒度规则见 CLAUDE.md。全程用中文。**未经用户确认，不修改、不删除任何文件。**

## 第 1 步：确定性检查

运行 `kb lint`，按 `issues` 整理问题：

- `error`：必须修复（失效链接、缺字段、要点没有来源、raw 被修改、index 过期、同名页面、文件名含禁用字符）。
- `warning`：值得一看（孤儿页、过长页面、iCloud 冲突副本、多余文件夹、空摘要）。

## 第 2 步：语义检查

读 `index.md`，再按需读页面，找出：

1. **重复页面**：两个页面讲的是同一件事（例如"RAG"和"检索增强生成"）。
2. **前后矛盾**：同一页面或不同页面的要点互相冲突。
3. **过时内容**：较新的来源已经推翻了较旧的说法。
4. **需要拆分**：页面超过约 2000 字，或明显包含两个独立的子话题。
5. **缺少链接**：页面明显相关，却没有互相出现在"相关"里。

只检查 wiki 页面，不改 raw/。"我的看法"和 `思考/` 里是用户原话，只能指出冲突，不能改写。

## 第 3 步：建议清单

把所有问题合成一份编号清单，每条写清楚：问题是什么、打算怎么改、会动哪些文件。例如：

```
1. [失效链接] [[主题/A]] 链接到不存在的 [[B]] → 改成 [[B 的正确页名]]
2. [重复] [[RAG]] 和 [[检索增强生成]] 讲同一件事 → 把后者的要点并入前者，后者改为指向前者的说明
3. [冲突副本] 主题/A 2.md → 对比后把差异合并进 主题/A.md，再删除副本
```

然后问用户："要执行哪几条？（例如：全部 / 1,3 / 都不要）"，**等用户回答**。

## 第 4 步：执行

- 只执行用户确认的条目。合并页面时，保留两边的所有来源。
- 删除文件（例如冲突副本、被合并的页面）前，再向用户确认一次具体文件名。
- 执行完运行 `kb index`，再运行 `kb lint --record`（同时记下本次体检的日期），确认 `errors` 为 0。
- 在 `log.md` 顶部写入 `## [YYYY-MM-DD] 体检 | 修复 N 项`，列出改了什么。
- 运行 `kb commit -m "[YYYY-MM-DD] 体检 | 修复 N 项"`。

用户一条都不执行时，仍然运行 `kb lint --record`，不写 log、不提交。
