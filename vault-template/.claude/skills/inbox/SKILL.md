# 处理收件箱

页面格式、目录约定和工作原则都写在 CLAUDE.md 里，本文只写流程。全程用中文和用户沟通。

所有 `kb` 命令都输出一行 JSON。`ok: false` 且 `error: "not_implemented"` 表示该功能还没开发，**跳过这一步，不要报错，也不要提起**；其他错误要写进报告。

## 第 1 步：开场

运行 `kb status`。

- 如果 `pending_question` 不为空：先把这个问题原样展示给用户（"上次的问题：……"），然后继续往下处理，不要停下来等。本次会话中用户只要回答了，就按"记录用户的回答"处理。
- 记下 `batch_limit` 和 `settings.projects`、`settings.life_categories`。

## 第 2 步：收集

1. 运行 `kb pull`。
2. 对 `kb status` 结果中 `needs_fetch` 为 true 的条目，逐个运行 `kb fetch <path>`。
3. 再运行一次 `kb status`，拿到最新的 `inbox.entries`（已按时间从旧到新排好序）。

## 第 3 步：逐条编译

按顺序处理 `inbox.entries`，**最多 `batch_limit` 条**，剩下的留到下次。跳过 `fetch_status` 为 `failed` 的条目，它们记入"失败"。

对每一条：

1. **读条目**：读取文件全文，判断它属于哪一类：

   | 类别 | 判断依据 | 去向 |
   | --- | --- | --- |
   | 文章 | kind 为 link，内容是观点、知识 | 主题页（或生活页）的"要点" |
   | 软件资源 | 介绍一个工具、软件、插件、网站 | `生活/软件工具清单.md` |
   | 生活事务 | 办事流程、健康、证件、社保等 | 对应的生活页 |
   | 想法 | kind 为 thought，是用户自己的话 | `思考/年-月.md` + 相关页面的"我的看法" |
   | 会议 | kind 为 meeting，或首行是"会议：项目名"，或文件名含"会议""纪要" | 项目页的"决策日志"和"待办" |

2. **写摘要并入库**：用一句话（30 字以内）概括这条内容，然后运行：

   ```
   kb file <path> --title "<标题>" --summary "<一句话摘要>"
   ```

   - 标题：文章和文件用原标题；想法用一个能概括它的短语（10 字左右）；会议用"项目名 日期 会议"。
   - 结果中 `duplicate: true` 表示这条内容以前入库过：**不要再写进任何页面**，记入报告的"重复"。
   - 记下返回的 `link`（例如 `[[raw/2026/10/2026-10-28-标题]]`），后面引用来源都用它。

3. **找候选页面**：读 `index.md`，再用 `rg -l "<关键词>" 主题 项目 生活 思考` 搜索 2–3 个关键词，找出最相关的已有页面。

4. **更新还是新建**（规则见 CLAUDE.md"主题页粒度"）：
   - 有相关的已有页面 → 更新它。
   - 和任何已有页面都不相关 → 用 `_templates/` 中的模板新建一个页面。
   - 拿不准该放哪 → 先放进最接近的页面，并记入报告的"待确认"。

5. **写页面**：
   - **文章**：在"要点"里加 1–3 条要点，每条末尾用括号注明来源 link。新建页面时同时写"一句话"。如果新内容和已有要点矛盾，两条都保留，并在新要点里写明"与上一条说法不同"。
   - **软件资源**：在 `生活/软件工具清单.md` 中按"工具名：一句话用途（来源 link）"追加一行；该文件不存在就用生活模板新建。
   - **想法**：在 `思考/年-月.md`（例如 `思考/2026-10.md`，月份取条目的日期）的对应日期小标题下追加一行 `- 原话 → [[关联页面]]`，**原话一字不改**。再到关联页面的"我的看法"里追加 `- 日期：原话（[[思考/年-月]]）`。找不到关联页面就只写思考日志，记入"待确认"。
   - **会议**：找到 `项目/<项目名>.md`（没有就用项目模板新建），在"决策日志"顶部按日期倒序追加决策，在"待办"里追加待办（`- [ ] 负责人：事项`），在"相关会议"里加上来源 link。项目名不在 `settings.projects` 里的，记入"待确认"。
   - 每改一个页面：更新 frontmatter 的 `updated`（今天）、把来源 link 加进 `sources`（不重复）、需要时补充 `tags`。新建页面要写好 `summary`。
   - 页面之间有关联的，在"相关"小节互相加上 `[[页面名]]`。

6. 记下这一条做了什么（新建或更新了哪个页面），用于日志和报告。

## 第 4 步：收尾

1. 运行 `kb index`。
2. 在 `log.md` 中"# 处理记录"标题和说明注释的下方、所有旧记录之上，写入本次记录：

   ```markdown
   ## [YYYY-MM-DD] 处理收件箱 | 入库 N，失败 M
   - 新建 [[页面]]
   - 更新 [[页面]]：一句话说明改了什么
   ```

3. 运行 `kb lint`。如果有 `error`，修好你本次造成的问题（例如漏写来源、链接写错），再运行 `kb index`。
4. 运行 `kb react`（标记飞书消息）。
5. 运行 `kb commit -m "<log.md 中本次记录的标题，去掉开头的 ## >"`。

## 第 5 步：报告和追问

输出处理报告：

```
## 处理报告

已入库（N）
- 标题 → [[去向页面]]

失败（M）
- 标题：原因 · 原链接（请用 Web Clipper 剪藏到 inbox/）

重复（K）/ 待确认（J）
- ……

还有 X 条留到下次处理。
```

没有内容的分组不写。最后提**一个**追问：

- 从本次入库的内容中，挑一条和用户已有"思考"或在做的项目最相关的。
- 问题类型限三种：关联（"这和 XX 项目有关吗？"）、立场（"你同意它哪一点？"）、行动（"你打算用在哪？"）。
- 运行 `kb question --set "<问题>" --related "[[相关页面]]"`。本次没有值得问的内容时，运行 `kb question --clear`。

如果 `kb status` 中 `lint_due` 为 true，在报告末尾加一句："距离上次体检已超过 N 天，可以说'体检'整理一下知识库。"

## 记录用户的回答

用户回答了追问（这次的或上次的）时：

1. 把用户的话**原样**追加到 `思考/年-月.md` 当天日期的小标题下：`- 原话 → [[追问的相关页面]]`。
2. 在相关页面的"我的看法"里追加 `- 日期：原话（[[思考/年-月]]）`，并更新该页面的 `updated`。
3. 运行 `kb question --clear`、`kb index`，然后 `kb commit -m "[YYYY-MM-DD] 记录想法 | <相关页面>"`。

用户没有回答，就什么都不做，不推测、不代写。
