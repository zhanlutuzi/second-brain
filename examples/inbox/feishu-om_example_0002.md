# 把知识编译一次，而不是每次重新检索

传统的 RAG 每回答一个问题，都要重新从原始文档里找片段、拼答案。问题越复杂，需要拼凑的片段越多，答案质量也越不稳定。

另一种思路是"编译"：每收进一份资料，就让模型读完它，把要点整合进一组结构化的页面里，标注来源，并更新相关页面之间的链接。之后回答问题时，先读这些已经整理好的页面，而不是原始文档。

作者把这比作编程：原始资料是源代码，整理好的页面是编译产物，规则文件是编译器的配置。好处是知识会不断累积，矛盾在入库时就被发现；代价是每次入库都要多花一些计算。

作者建议在个人或小团队规模下优先尝试这种方式，并保留原始资料，方便随时重新编译。
