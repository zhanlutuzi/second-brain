# 长上下文会取代 RAG 吗

过去两年，模型的上下文窗口从几千个 token 扩展到了上百万个 token。很多人因此认为，检索增强生成（RAG）已经没有必要：既然能把所有资料一次性放进上下文，为什么还要先检索？

作者认为答案取决于规模。对个人来说，一个人一辈子写下的笔记和收藏，换算成文本大多在几百万字以内，整理得当的话，相关部分完全可以直接放进上下文，省掉切分、向量化和召回调优这些工程工作。

但对团队和企业，资料量往往是个人的成百上千倍，而且每天都在变化。把所有内容都塞进上下文，成本和延迟都无法接受，检索仍然是必要的第一步。

文章的结论是：长上下文降低了小规模知识管理的门槛，但不会让检索消失；两者会长期共存，按规模选择。
