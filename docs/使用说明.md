# 第二大脑 · 使用说明

这份说明面向使用者：怎么装、每天怎么用、升级会动什么、出了问题怎么办。设计细节见 [PRD.md](PRD.md) 和 [TECH.md](TECH.md)。

---

## 一、它是什么

你在手机上把看到的链接、想法、文件随手发进一个飞书群（或者用 Web Clipper 剪藏）。电脑开着时，对 Claude Code 说一句"处理收件箱"，它会：

1. 拉取飞书群里的新消息；
2. 抓取链接的正文；
3. 把原文存进 `raw/`，再把要点整理进主题页、项目页、生活页，每条要点都标明出处；
4. 给处理过的飞书消息加一个表情；
5. 输出处理报告，并问你一个问题。你的回答会一字不改地记进"思考"。

内容都是普通的 Markdown 文件，用 Obsidian 浏览，随 iCloud 同步到其他设备。

---

## 二、东西都存在哪

| 内容 | 位置 | 同步方式 | 说明 |
| --- | --- | --- | --- |
| 知识库（vault） | 默认 `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/我的第二大脑` | iCloud | 你的全部笔记，手机上的 Obsidian 也能看 |
| 处理进度 | vault 里的 `.kb/state.json` | 跟 vault 一起走 | 飞书游标、待加的表情、上次的追问、体检日期、最近一次是哪台电脑处理的。Obsidian 里看不到这个文件夹 |
| 飞书凭证 | 每台电脑的 `~/.second-brain/.env` | 不同步 | App ID 和 App Secret，文件权限 600，只存在本机 |
| 浏览器登录状态 | 每台电脑的 `~/.second-brain/browser/` | 不同步 | 抓公众号等网页用的 Chromium 配置 |
| 版本历史（可选） | 每台电脑的 `~/.second-brain/vault.git` | 不同步 | 默认不开启，见第九节 |
| 程序（kit） | `~/second-brain-kit` | GitHub | 只有代码和模板，不含任何个人内容 |

一句话：**笔记和处理进度跟着知识库走，密钥跟着电脑走，代码跟着 GitHub 走。**

## 三、安装

### 需要准备

- 一台 Mac，装好 [Homebrew](https://brew.sh)，再用它安装 Node.js：

  ```bash
  brew install node
  ```

- [Claude Code](https://claude.com/claude-code)，并已登录；
- [Obsidian](https://obsidian.md)。想在手机上看，就在 iPhone 上装 Obsidian，并新建一个保存在 iCloud 的库。

### 第一台电脑

```bash
git clone https://github.com/zhanlutuzi/second-brain.git ~/second-brain-kit
```

```bash
cd ~/second-brain-kit && claude
```

在 Claude Code 里输入 `/setup`，选择"新建 vault"，然后一问一答走完。它会依次：

- 安装依赖，并让 `kb` 命令可用；
- 安装抓网页用的 Chromium；
- 创建 vault；
- 配置飞书（可以跳过）；
- 在 `~/.zshrc` 里加一个 `kb-open` 命令；
- 用示例数据试跑一次。

### 第二台电脑

同样 clone kit、运行 `/setup`，这次选择"使用已有的 vault"：

- 等 iCloud 把 vault 同步过来（vault 里能看到 `我的设置.md`）再开始；
- 不需要新建 vault，处理进度会随 iCloud 一起过来；
- 飞书凭证只存在本机，所以要再填一次。

### 建议做的一个设置

在 Finder 里右键 vault 所在的文件夹，选择"**保留下载**"。否则开着"优化 Mac 储存空间"时，iCloud 可能把不常用的文件只留在云端，处理时读起来会很慢。

## 四、每天怎么用

打开终端，运行 `kb-open`（或者 `cd` 进 vault 后运行 `claude`），然后直接说下面这些话。

### 处理收件箱

说"处理收件箱"。一次最多处理 `batch_limit` 条，默认 30 条，剩下的留到下次。处理完会给出这样一份报告：

```
## 处理报告

已入库（12）
- 长上下文会取代 RAG 吗 → [[长上下文与 RAG]]

失败（1）
- 某篇公众号文章：browser: verification_page · 原链接（请用 Web Clipper 剪藏到 inbox/）

待确认（1）
- 一条语音消息：暂不支持，请手动处理

还有 3 条留到下次处理。
```

报告最后会问你**一个**问题，例如"你同意它哪一点？"：
- 你回答了：原话一字不改地记进 `思考/年-月.md`，并链接到相关页面；
- 你不回答：什么都不记，下次处理时会再提一次，然后清掉。

飞书群里，入库成功的消息会被加上一个表情（默认 `OK`），抓取失败的加上另一个（默认 `CRY`），在手机上一眼就能看出哪些已经入库。

### 提问

直接问，例如"读书会小程序为什么延期""我之前看过哪些关于间隔重复的内容"。

- 每个说法后面都附上出处链接；
- 项目类问题会按日期列出决策时间线；
- 知识库里找不到依据时，会直接说"知识库里没有"，不会拿常识冒充。

想把回答保存下来，就说"把这个回答存下来"，它会存成一个新的主题页。

### 每周回顾

说"每周回顾"，会列出本周新增了什么、你写下的原话、和以前看法有冲突的地方、还没回应的事项。**只出报告，不改任何文件。**

### 体检

说"体检"，会先检查失效链接、缺少属性、要点没有出处、iCloud 冲突副本等问题，再检查重复、矛盾、过时、过长的页面，最后给出一份编号的建议清单。你说要执行哪几条，它才动手；删除文件前还会再确认一次。

距离上次体检超过 `lint_interval_days` 天（默认 30 天）时，处理报告末尾会提醒你。

## 五、怎么收集

### 发进飞书群

| 你发的 | 系统怎么处理 |
| --- | --- |
| 带链接的文字 | 每个链接一条，抓取正文；链接以外的文字作为备注保留 |
| 不带链接的文字 | 当作你的想法，原话记进"思考" |
| 文件 | 下载下来；`.md`、`.txt` 文件的内容会直接作为正文；PDF 等交给 Claude 阅读 |
| 会议纪要 | 文件名里有"会议"或"纪要"，或者正文第一行写"会议：项目名"，就会把决策和待办追加到对应的项目页 |
| 图片 | 下载下来，交给 Claude 看图后归类 |
| 合并转发的聊天记录 | 展开成文字，当作一条想法 |
| 语音、视频、表情包、卡片等 | 暂不支持，会在报告里提醒你手动处理 |

不需要打标签，也不需要按什么格式发。

### 用 Web Clipper 剪藏

装好 [Obsidian Web Clipper](https://obsidian.md/clipper)，把保存位置设为 vault 的 `inbox/` 文件夹。剪藏的网页下次处理时会一并入库。

抓取失败的链接（例如需要登录或验证的页面）就用这种方式补上。

## 六、知识库里有什么

```
我的第二大脑/
├── CLAUDE.md        给 Claude 的规则（升级时更新；末尾"个人补充"区块归你）
├── 我的设置.md       你的配置（见第七节）
├── index.md         总目录，自动生成，不要手改
├── log.md           处理记录，最新的在最上面
├── inbox/           待处理的条目
├── raw/             原文，按 年/月 存放，只增不改；附件在 raw/assets/
├── 主题/            知识类页面：一句话 · 要点（带出处）· 我的看法 · 相关
├── 项目/            一个项目一页：概况 · 决策日志 · 待办 · 相关会议
├── 生活/            社保、健康、证件、软件清单等事务
├── 思考/            按月一个文件，只记你的原话
└── _templates/      四种页面的模板
```

几条规则：

- `raw/` 里的原文入库后不再修改，体检会检查有没有被改过；
- 新内容优先更新已有的页面，而不是新建页面；
- "我的看法"和 `思考/` 里只放你的原话，AI 不代写、不润色；
- 你可以随时在 Obsidian 里自己改页面，改完说一声"体检"就能查有没有破坏链接。

## 七、我的设置.md

这是唯一需要你自己改的文件。改上面那段属性（`---` 之间的部分），下面的正文可以随便写备注。

| 属性 | 默认值 | 含义 |
| --- | --- | --- |
| `feishu_chat_id` | 空 | 飞书收件箱群的 ID，以 `oc_` 开头。`/setup` 或"配置飞书"时自动填写 |
| `reaction_ok` | `OK` | 入库成功时给飞书消息加的表情 |
| `reaction_failed` | `CRY` | 抓取失败时加的表情 |
| `browser_domains` | 公众号、小红书 | 这些网站直接用浏览器抓取 |
| `browser_headless` | `true` | 浏览器是否在后台运行。需要手动登录或过验证时改成 `false`，浏览器窗口会显示出来 |
| `projects` | 空 | 你在做的项目，会议纪要会归到同名的项目页 |
| `life_categories` | 社保医保、健康、证件与办事、软件工具 | 生活页的分类 |
| `batch_limit` | `30` | 每次处理收件箱最多处理多少条 |
| `lint_interval_days` | `30` | 距离上次体检超过多少天就提醒 |
| `version_history` | `false` | 是否用 git 记录每次处理，见第九节 |

飞书的 App ID 和 App Secret **不写在这里**，它们只存在每台电脑的 `~/.second-brain/.env`。要修改，就在 vault 里说"配置飞书"。

## 八、升级

### 平时：一条命令

在 vault 目录运行：

```bash
kb upgrade
```

或者在 Claude Code 里说"升级"。它会自己完成：

1. 在 `~/second-brain-kit` 拉取新代码，并安装依赖；
2. 用新版本更新 vault 里的系统文件；
3. 给你的配置补上新版本新增的设置项；
4. 迁移旧版本的数据（如果有）。

**有两台电脑的话，两台都运行一次**：它会更新那台电脑上的程序。vault 本身已经随 iCloud 同步过去，不会被重复修改。

升级后重新启动 Claude Code，新的 skill 才会生效。

### 升级会动什么、不动什么

| 类别 | 文件 | 升级时 |
| --- | --- | --- |
| 系统文件 | `CLAUDE.md` | 换成新版规则；"个人补充"标记之后你写的内容**原样保留** |
| 系统文件 | `.claude/`（skill 和权限设置）、`_templates/` | 整个替换成新版 |
| 你的配置 | `我的设置.md` | 只**追加**缺少的新设置项（用默认值），已有的值一个都不改 |
| 你的配置 | `.gitignore` | 只**追加**缺少的条目，已有的不改 |
| 你的内容 | `主题/` `项目/` `生活/` `思考/` `raw/` `inbox/` `index.md` `log.md` | **完全不动** |
| 本机设置 | `~/.second-brain/.env`、浏览器登录状态 | **完全不动** |

所以：

- 想加自己的规则，写在 `CLAUDE.md` 末尾的"个人补充"里，不要改 `.claude/` 里的文件，那里的内容升级时会被覆盖；
- 不要直接改 `~/second-brain-kit` 里的文件。改了的话，`kb upgrade` 会因为无法自动合并而停下来，并告诉你是哪些文件。这时 vault 一点都没动。

### 想更保险：升级前备份

```bash
ditto "$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/我的第二大脑" "$HOME/Desktop/第二大脑备份-$(date +%Y%m%d)"
```

路径按你的 vault 实际位置修改。

### 从 v0.1.0 升级（只有这一次要多一步）

v0.1.0 的 `kb upgrade` 还不会自己拉取新代码，所以第一次要先手动更新程序：

```bash
cd ~/second-brain-kit && git pull && npm install
```

然后在 vault 目录运行 `kb upgrade`。这一次它还会：

- 把本机 `~/.second-brain/state.json` 里的处理进度并入 vault 的 `.kb/state.json`，原文件改名为 `state.json.migrated` 保留；
- 删除旧版放在 vault 里的 `.git` 指针文件。原有的 git 历史仍在 `~/.second-brain/vault.git`，想继续记录就把 `version_history` 改成 `true`。

第二台电脑同样先手动 `git pull && npm install` 一次，以后就只需要 `kb upgrade`。

## 九、两台电脑、版本记录与找回

### 两台电脑

- 任何一台装了 kit 的电脑都能处理收件箱，处理进度在 vault 里共享，不会重复拉取。
- **不要两台同时处理。** 另一台电脑 10 分钟内刚处理过时，Claude 会提醒你等 iCloud 同步完再处理。
- 万一同时处理了，可能出现"文件名 2.md"这样的 iCloud 冲突副本，`.kb/` 里也可能出现 `state 2.json`。说"体检"，会找出这些副本并提示你合并。

### 版本记录（可选）

默认关闭。打开方法：把 `我的设置.md` 里的 `version_history` 改成 `true`。打开后：

- 每次处理收件箱、每次体检都会提交一次，提交说明和 `log.md` 的标题一致；
- 历史存在**每台电脑本机**的 `~/.second-brain/vault.git`，vault 里不放任何 git 文件；
- 两台电脑各记各的。在一台上回滚时，另一台同步过来的修改也会被回滚，回滚前请确认。

### 不开版本记录时怎么找回

- Obsidian 自带的核心插件"**文件恢复**"（设置 → 核心插件 → 文件恢复）会自动保存每个文件最近的快照，可以在里面找回旧版本；
- 原文永远在 `raw/` 里，页面坏了可以从原文重新整理。

## 十、常见问题

**`kb: command not found`**
在 kit 目录运行 `npm link`；报权限错误就运行 `sudo npm link`。

**飞书消息拉不下来**
在 vault 目录运行 `kb pull --dry-run`，看返回的 `message`。常见原因：
- 应用权限没开通；
- 版本没发布；
- 机器人不在群里；
- `feishu_chat_id` 填错了。

**第一次拉取把群里的历史全拉下来了**
没有游标时，会从头拉取。只想要某天之后的，可以先运行 `kb pull --since 2026-10-01`。

**公众号文章抓取失败**
1. 确认装过浏览器：

   ```bash
   cd ~/second-brain-kit && npx playwright install chromium
   ```

2. 还不行，把 `browser_headless` 改成 `false` 再处理一次，必要时在弹出的浏览器里手动完成验证，验证状态会保存下来；
3. 仍然失败，就用 Web Clipper 剪藏到 `inbox/`。

**在另一台电脑上处理时提示"刚有另一台电脑处理过"**
等几分钟，确认 iCloud 同步完成（Finder 里 vault 文件夹旁边没有上传图标）再处理。

**`kb upgrade` 报 `kit_update_failed`**
你或者别的程序改过 `~/second-brain-kit` 里的文件。先看改了什么：

```bash
cd ~/second-brain-kit && git status
```

确认不需要这些修改，就丢弃它们（这一步会丢掉 kit 目录里的修改，不影响 vault）：

```bash
cd ~/second-brain-kit && git checkout -- .
```

然后再运行一次 `kb upgrade`。

**出现了"文件名 2.md"**
这是 iCloud 的冲突副本：两台设备同时改了同一个文件。说"体检"，会提示你合并。

## 十一、kb 命令速查

日常不需要手动敲这些命令，Claude 会替你调用。排查问题时可以在 vault 目录里直接运行。每个命令都输出一行 JSON。

| 命令 | 作用 |
| --- | --- |
| `kb status` | 收件箱里有多少条、上次体检日期、未回复的追问、最近一次处理的电脑 |
| `kb pull [--dry-run] [--since 日期]` | 拉取飞书新消息到 `inbox/`；`--dry-run` 只看不写 |
| `kb fetch <文件>` | 抓取一条链接的正文 |
| `kb file <文件>` | 把一条内容存进 `raw/` |
| `kb index` | 重新生成 `index.md` |
| `kb lint` | 体检里的确定性检查 |
| `kb react` | 给处理过的飞书消息加表情 |
| `kb commit -m 说明` | 提交一次（仅在打开版本记录时） |
| `kb question --set 问题 / --clear` | 记录或清除追问 |
| `kb init <路径>` | 新建一个 vault |
| `kb upgrade` | 升级 |
| `kb config --app-id … --app-secret … --chat-id …` | 保存飞书配置 |
| `kb --help` | 查看全部命令 |

## 十二、隐私与安全

- 你的笔记只存在你的 vault 和 iCloud 里，不会进入 GitHub 上的 kit 仓库；
- 飞书 App Secret 只存在本机的 `~/.second-brain/.env`，文件权限 600，所有输出里都会打码；
- 内容会发给 Claude 做整理，请按你对 Claude Code 的使用习惯，决定哪些内容适合发进收件箱；
- Claude 只被预先允许运行 `kb`、`rg` 和查看、提交类的 git 命令，删除文件前总会先问你。

## 十三、不想用了

- 删除 `~/second-brain-kit` 和 `~/.second-brain`；
- 运行 `npm unlink -g second-brain-kit` 去掉 `kb` 命令；
- 在 `~/.zshrc` 里删掉 `kb-open` 那几行。

你的知识库就是一个普通的 Markdown 文件夹，留着它，Obsidian 照样能打开。
